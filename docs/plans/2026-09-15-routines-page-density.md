# Family routines board density fix — tracking

Owner (2026-09-15, photo of the wall tablet): `/hub/routines` looks nothing like `Actieve routines.dc.html` — fonts enormous, card title clipped, colours off, columns overflow. Orchestrator mode; cap 3 (scout + builder + main-thread screenshot review).

## Root cause (scout)

`[data-surface='hub']` scales every `--text-*` token for 2 m viewing (h1 48px, h3 28px, body 22px). `RoutineCard` titles use `text-h1`, `StepRow` tile titles `text-h3`, the board's labels `text-h3`/`text-body-sm`; `dense` only changes layout. Fixed-px elements (medallions, bars, pills) already match the mockup. The expanded card also draws a left rail the mockup does not have. No visual e2e spec existed for the family `/hub/routines` or `/hub/taken` — the earlier plan promised them and I never checked; the reviewer only saw `[memberId]` baselines.

## Decisions

- ~~compact scope~~ Owner (2026-09-15): remove the hub type inflation altogether — delete the `[data-surface='hub']` `--text-*` block in `tokens.css`; every hub page renders at the app's base scale. All hub visual baselines regenerate. Kiosk-audit font floor: builder reports, main thread decides.
- `RoutineCard dense`: no rail, medallion ≈52px, wrapping title. `StepRow` tile 64px when dense.
- `/hub/routines/[memberId]` untouched.
- `/hub/taken`: builder checks its mockup; same scope only if the mockup is compact too.
- Visual specs: `hub-routines-family-*` and `hub-taken-*`; baselines generated by main thread and compared against the mockup by eye before merge.
