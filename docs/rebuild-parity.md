# Legacy Rebuild Parity Checklist

Date: 2026-08-06

This is a flat inventory of every user-facing capability found in the legacy Kynite app (this repo, pre-rebuild). It was compiled by reading the route tree, components, server services, i18n message files, and E2E specs. Each item cites the legacy source file/route that proves the behavior exists.

**Verification note**: This list started as a discovery artifact. In the final milestone of the rebuild, every item below had to be re-verified one by one against the greenfield app — this file is not itself proof the rebuild is done, only proof of what legacy did, plus (as of M18) what the rebuild does about it.

Every one of the 167 items below now carries an explicit verdict, appended to the item after an em dash, with one line of evidence. ### The thirty open fails, resolved — 2026-08-07

The first pass of this milestone left thirty genuine gaps unchecked, listed here so the decision was recorded rather than implied. **Owner decision, 2026-08-07 (binding): fix the cheap batch plus Google attendee ingestion; sign off the remainder as intentionally dropped.** Twenty were fixed and now read **pass** with evidence; ten are signed off and read **dropped**, each carrying "signed off by owner 2026-08-07" and a one-line rationale. Zero remain.

**Fixed (20).** Error surfaces (route, global and a self-recovering kiosk boundary, plus a localized 404 and the `errors` namespace); destructive confirmations (a new `AlertDialog` primitive behind unlink-account, remove-calendar and delete-event, plus the M12 two-tap extracted as `ConfirmButton` for the three list deletions that still fired on the first press); Google `eventType` filtering; Google attendee ingestion with a migration that backfills events imported before it; toasts mounted for the parent app and wired to every settings save; device rename and `pairedAt`; the `callbackUrl` round trip; a greeting on `/today`; timer extend; the brand mark in both shells; sync-status and link badges; the event description input; and an interactive month "+N more".

**Signed off as dropped (10).** Event drag-resize; the hub week board (FR3 is met by the day board + agenda together, which cover the wall use case); the user menu; a read-only event-details view; the category filter; the birthday banner; agenda grouping and search; quick-actions; the channel-health read surface; and — folded into the sync-status item rather than dropped separately — the transient `syncing`/`conflict` badge states.

Two `changed` verdicts were flagged as judgement calls worth re-reading rather than accepting silently, and both were **confirmed by the owner on 2026-08-07**: the 12/24-hour preference stays purely locale-derived with no override, and Now/Next/Later stays replaced by plain chronological columns.

### Beyond parity — M18 also closed

Six things in this milestone are not legacy-parity items at all. They are recorded here because this file is where the milestone's evidence lives.

1. **PRD FR22, push-on-participant-action.** `docs/prd.md` requires it verbatim, `docs/rebuild-milestones.md` recorded it as unowned at M11 and again at M12, and the push pipeline fired only for reminders and redemption requests — a child tapping "done" notified nobody, so Journey 1's payoff never happened. A routine-step completion now fans out to every *other* adult, one `push:send` job per endpoint, gated on a third preference column (`notification_preference.completion_updates`, default true, `drizzle/0012_overjoyed_mad_thinker.sql`) and idempotent per completion `clientId` — a replayed tap from the offline outbox notifies nobody a second time. Copy is neutral and factual in both locales ("Bram heeft tanden poetsen gedaan"), never addressed to the child and never sent for a *missed* step. Evidence: `src/modules/notifications/jobs.ts#notifyRoutineCompleted`, `src/modules/routines/notify-bridge.ts`, tests/integration/completion-notifications.test.ts, tests/integration/routine-completion.test.ts ('notifies the other adults once — and not again on a replay').
2. **Calendar import default.** Every calendar discovered from Google's calendar list took the column default `syncEnabled: true`, so linking a work account put a dozen colleagues' shared diaries, meeting rooms and holiday feeds on the family board at once. A *new* row now takes its initial state from Google's own answer — `primary` or `selected` — and an existing row is never re-decided by a discovery pass (`src/modules/google/domain/calendar-list.ts#initialSyncEnabled`, `sync.ts#discoverCalendars`).
3. **Switching a calendar off now empties it.** `syncEnabled` governed only ingest, so a parent who muted a calendar in settings watched its already-imported events keep rendering on the wall. Disabling now deletes that calendar's events and clears its sync cursor in one transaction (so re-enabling is a full pass rather than an incremental one that would restore nothing), stops the channel, and publishes `settings.updated` once instead of one `event.deleted` per row. `listEvents` carries a matching predicate as a safety net. Native events (`calendar_id IS NULL`) are untouched. Evidence: tests/integration/google-calendar-toggle.test.ts.
4. **Attribution backfill.** Incremental sync never revisits an unchanged Google event, so events imported before attribution existed would have stayed in nobody's column forever. `drizzle/0013_backfill_google_event_attribution.sql` is a single statement that attributes exactly the rows nobody has ever attributed (`owner_member_id IS NULL AND cardinality(attendee_member_ids) = 0`), which is the same invariant the sync upsert enforces — so it cannot overwrite a parent's own choice.
5. **Two new shared primitives.** `src/components/ui/alert-dialog.tsx` (modal, `role="alertdialog"`, for actions that take *other* data with them and need a sentence with a number in it) and `src/components/ui/confirm-button.tsx` (the M12 two-tap, extracted, for one row in a list). Weight matches stake; the choice between them is documented in both files.
6. **`src/components/ui/textarea.tsx`**, the sibling of `input.tsx`, so the event description had somewhere to be typed.
